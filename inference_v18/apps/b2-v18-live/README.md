# 本机 B2 + A3 v18 联合控制

入口：http://127.0.0.1:8881/ 。机械臂控制台：http://127.0.0.1:8879/ 。

部署日期：2026-11-12。联合管理策略采用最新 v18 的保存最佳累计 24500 次（本段 24000 次），不是最后一次权重。来源和完整哈希在 `models/manifest.json`；源检查点 SHA256 为 `d5540cc2f1a8a283c38c9e644c9693d2b6317158d9beb2172f6d67c0594da703`。管理策略在 PC 上推理，B2-P4 在狗端执行。世界模型用于训练，实机推理不在线更新网络。

## 使用

1. 保持机器狗原生模式稳定站立、遥控器回中并松开按键。点击主页面的“进入联合待命 · 狗 + 机械臂”。本次点击会真实执行：先让机械臂以控制器 5% 速度到达 `[0, 1.05, -1.5, 0, .45, 0]` rad，再切换 P4、发送零平移/零转向/回正/标准高度命令，连续确认稳定 1 秒后停止更新并保持。期间不运行 v18 到点 Actor，不追踪页面中的旧目标。
2. 页面显示“联合待命就绪”后，点击“启用键盘控制”。目标同步为当前 EE 位姿；首次按下运动键才运行 v18 联合追踪。也可展开“数值目标与准备”，输入 XYZ 与朝向，预览并确认执行。
3. 准备任一步失败，后续步骤不启动。取消、页面失焦或断连会中止准备。机械臂先准备失败时狗仍保持原生；P4 已经接管后若未确认稳定，则停止平移/转向并报告失败，不自动趴下或尝试切回原生。
4. “停止”终止机械臂任务，将狗的平移与转向归零、保持机体姿态。“交回遥控器”解除网页控制；R2+Y 按原流程恢复原生。原遥控器按键均未修改。原生/外部接管后需重新进入联合待命，服务重启不会自动重新切换或移动。

当前运行三个用户服务：`b2-live-tunnel`、`carm-console`、`b2-v18-live`。它们在后台运行，本次未设置 PC 开机自动启动。依赖本机保持运行、两根网络连接及 SSH 隧道。重启服务不会恢复旧任务。

## EE 键盘控制（2026-11-12）

默认入口改为 EE 空间控制台。启用时复制真实反馈计算的当前 TCP 位姿；启用本身不发送运动命令，首次按下映射键时才建立联合策略跟随。键盘改变的是目标 EE 位姿，99 维观测 → 原 v18 管理 Actor → P4 机体命令与 A3 六关节目标，未接入另一套解析 IK 或改变权重、随机化、训练限位。

| 按键 | 目标变化 |
| --- | --- |
| W / S | 参考坐标 +X / −X |
| A / D | 参考坐标 +Y / −Y |
| R / F | 参考坐标 +Z / −Z |
| ↑ / ↓ | 围绕末端横轴（局部 −X / +X）俯仰 |
| ← / → | 围绕参考 +Z / −Z 偏航 |
| O / P | 围绕末端指向轴（局部 +Z / −Z）旋转 |
| Esc | 停止狗与机械臂联合动作 |
| 空格 | 夹爪张开 40 mm / 闭合 0 mm 切换；5 N 力限制 |

目标平移 5 cm/s、朝向 10°/s，组合键归一化。末端 +Z 是此模型 TCP 指向，O/P 绕该轴旋转、保持其指向；目标朝向按 SO(3) 旋转积分，不以欧拉角直接相加。指向接近参考竖直轴时，参考 yaw 对指向的作用自然减小，这是旋转几何特性。

松键保持目标，策略继续跟踪最后目标，满足 ≤1 cm / ≤10° 同时保持 1 秒后停止发送运动并保持；再次按键可启动下一段。目标落后反馈超过 10 cm 或 15° 时暂停目标递增并显示原因，防止长时间按键积累远目标；原任务水平 3 m、高度 0.1–1.6 m 的范围不变。目标停止更新 12 秒仍未达到原成功判据则报告 POLICY_NOT_CONVERGED，不宣称解析 IK 无解。

浏览器失焦、页面隐藏、输入框获得焦点会关闭键盘控制；350 ms 未收到按键状态帧会停止，重新连接不自动恢复。狗/臂已有 150 ms 执行租约与硬件反馈保护保留。输入框打字、系统快捷键不触发运动。数值目标、准备姿态和重置需要先关闭键盘。

界面显示 J1–J6 实际角度与物理上下界。JOINT_LIMIT 指定越限关节与角度；JOINT_COMMAND_MARGIN 指示向保护余量外继续运动的请求；JOINT_FOLLOWING_ERROR 指定反馈滞后的关节。连杆间距与离地约束显示具体连杆/间距，不虚构单一责任关节。策略未收敛且没有检测到关节约束时明确说明“无法归因到具体关节”，不能据此证明目标物理不可达。

本次修复旧控制循环中 `abs(list)` 的姿态检查错误，避免在首帧前退出。通过 29 项管理策略/键盘/租约测试、浏览器按键状态测试和 8 组原训练输出对照。测试覆盖启用不运动、首键进入联合策略、运行中按键失联停止两端、启动中取消、组合方向与旋转、具体关节/碰撞错误。测试使用离线夹具；页面更新后未代用户发送实机动作。结果保存在 `diagnostics/v18_keyboard_20261112/`。

## 一键联合待命更新

2026-11-12 新增 `enter_standby` 操作。初始检查沿用原生稳定站立、实际传感器、P4 哈希、机械臂位置模式与工具坐标要求；复用原机械臂准备路径检查。完成机械臂准备且停止确认后才请求狗端 `begin`。待命阶段的机体命令始终为六维零值，由 P4 原有姿态过渡处理，不运行管理策略到点推理。

## 空格夹爪开合更新

空格是单次按下触发，长按不重复，输入框及 Ctrl/Alt/Meta 快捷键不触发。页面也提供同等开合按钮。无需启用 EE 键盘即可独立操作夹爪；同一页面的联合跟随中也可操作，机械臂准备期间或其他会话占用时拒绝。Esc 和停止按钮继续停止联合动作，不自动松开夹爪或改变抓持目标。

使用控制器实际 `getEeffParams` 限位与 `eeff_pos` 米制反馈，发送原厂 `setEffectorCtr`（`control_motor=false`，位置 0/0.04 m，`vel=[0]`，`tau=[5]`）。复用此前真实夹爪开合验证参数，不发送六关节目标，不自动复位/使能。前端提交明确开/合目标，后端按请求编号去重，超时不自动重发。页面区分请求应答、实际开口与未到达；闭合受阻不当成抓取成功。

本次通过 36 项机械臂接口测试、44 项联合控制测试及浏览器按键状态测试；部署后只读核对真实夹爪反馈和页面。未发送实机开合、关节或机体动作。记录位于 `diagnostics/v18_gripper_key_20261112/`。

## 遥控器最高优先级（2026-11-12）

删除的是本次实际触发的“联合待命零速站立期间机体水平偏移超过 10 cm”终止判定。仍检查稳定站立、机体高度/倾角、关节与碰撞、反馈有效性等条件；EE 键盘目标超前反馈的 10 cm 限制属于另一项目标积分规则，未更改。

狗端以 50 Hz 控制周期检查所有遥控按键及四轴任何非零数值（无额外摇杆阈值），立即释放联合/原地选点控制覆盖层，使原键位与摇杆在同周期生效。遥控持续输入时拒绝网页或 API 新动作，首次完全回中、松开所有按键后连续 2 秒才重新开放；新输入重置计时。代次编号使页面漏采到短暂按键时仍可撤销旧目标。遥控器反馈失效时暂停外部控制，恢复后同样确认连续静默 2 秒。

机械臂服务独立订阅狗端仲裁状态（50 ms 查询间隔，200 ms 状态失效判据），覆盖联合流、准备、独立机械臂控制台和夹爪入口；遥控接管时停止臂任务，在夹爪尚在执行开合时保持当前实际开口，不自动张开。机体由狗端本地接管，臂/夹爪的响应另外包含局域网与控制器停止应答延迟。

2 秒后恢复操作资格，不重放旧轨迹或积压指令。若此前启用了 EE 键盘、网页仍前台且狗仍是 P4，自动以当前 EE 位姿重新启用键盘；运动键需松开再按。若遥控器已切回原生，则尊重该模式，需要再次显式进入联合待命才启用 EE。夹爪与数值/准备按钮会随仲裁自动恢复可用。

狗端部署保留旧 release，策略权重和遥控器键位未更改。离线测试及部署记录：`diagnostics/v18_remote_priority_20261112/`。
