## 姿态编排

选择左倾、右倾、前俯或后仰，输入 0–30° 内的角度（支持小数），添加后可上移、下移或删除。草稿仅保存在浏览器，编辑和刷新不执行动作。机器人稳定四足站立时，点击“确定并执行”提交整份编排；此后的草稿修改不影响已确认的任务。

可以选择“每步回正站稳”或“连续切换、最后回正”。开始后先执行训练中的 2 秒零角度准备段；每一步包含 4 秒转入和保持。保持原 Actor 的零角度回正与平衡；当前四足站姿和稳定性通过后，交回原生经典行走模式，遥控器可继续移动。遥控器组合键继续按原映射中断或接管，没有新增操作解锁或实机验证审批条件。

姿态 Actor SHA256：`746fef2b973f8f590ff1d5c89b55923e3e776a5d3e8316942f17be14e8b58bd3`。导出保留 10 帧本体观测、6 维命令、原命令动态和动作映射。该任务使用训练中的 200 / 200 / 300 Nm 每腿限幅，未套用旧后腿任务的功率 envelope。它们是仿真实验预算，不是厂家额定参数。基础严格评测 117/1056，脚位偏移未达标；推理和编排检查不代表实机验证通过。执行过程记录在 `attitude_trace.jsonl`。

## 用户指定的操作条件

- 切换原生 / 自训练 locomotion：机器人处于四足站立姿态。
- 执行后腿站立：机器人处于稳定四足站立姿态。
- 经典模式入口：选择后双击遥控器 R1，两个策略入口一致。
- 其他按键保留原生功能。自训练控制期间收到恢复站立、站立/趴下、自由行走、姿态、奔跑或视觉行走按键时，交回原生控制执行对应功能。

版本 `20261101_v4` 按用户要求移除了额外的实机验证凭据门槛、连续稳定 2 秒、摇杆回中要求、动作阶段互锁、页面版本号门槛、停止后 R1 重新解锁、永久故障/阻尼锁定，以及应用额外添加的运动中倾角、单步关节变化和恢复时限截断。网页仅保留用户要求的策略选择与后腿动作按钮；额外网页急停和停止入口已移除。原生 L2+B 保留为阻尼模式，可用原生恢复按键退出；再次从站姿双击 R1 也可进入已选择的自训练经典模式。

站姿由当前关节位置与 IMU 倾角识别；稳定性由关节速度、角速度和可用的平移速度识别。没有固定等待时间。根部位置不是 locomotion 站姿识别的前提；后腿模型读取持续运行的 `rt/odommodestate`（备用同源 `rt/lf/odommodestate`），不再依赖随原生控制退出而停止的 `sportmodestate`。里程计位置按起始 IMU 航向差转换到策略坐标系，平移原点由原模型锚定。位置缺失时报告数据不可用，不使用伪造位置。无法读取当前本体数据时不将旧姿态报告为站立。数据恢复后自动继续计算，不需要解锁。

控制权交接遵循 SDK 的释放/选择协议；不会同时让原生与自训练发布电机目标。SDK 调用失败仅报告本次执行结果，允许后续正常指令。交接中后到达的 L2+B 取代旧指令，但不设置永久阻止接管的状态。原生正在控制时，网站不重复发送原生已经收到的遥控指令。

自训练速度仍遵循用户指定的合成 XY ≤ 2 m/s、|vy| ≤ 0.6 m/s；策略保留训练时的动作映射与关节范围。内部计算需要有效的模型输入与有限数值，这些错误不转化为验证审批或故障锁定。

## 运行

```bash
# 在项目根目录启动本机控制台；加载模型，不连接机器人。
bash apps/b2-console/start_console.sh

# 机器人上由用户级 systemd 服务管理。
/usr/bin/python3 /home/unitree/supermimic_b2/console/current/server.py --backend sdk --port 8765 --bundle /home/unitree/supermimic_b2/current

# 操作电脑上的 SSH 转发。
ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 unitree@192.168.123.164
```

浏览器打开 `http://127.0.0.1:8765`。服务只监听 loopback，沿用 SSH 访问和 HTTP 同源校验。请求编号用于避免网络重传重复执行，服务器可自动生成；状态版本不是操作条件。网页断开时显示数据不可用，连接恢复后自动更新；遥控器处理在机器人服务端进行。

服务启动只订阅状态并查询控制器；只有实际操作入口才能接管。独立发布线程按当前策略目标发送指令；仅操作员的 L2+B 切换到阻尼输出。数据无法用于推理时停止提交模型目标，恢复后继续。没有应用新增的自动阻尼或故障永久锁。

`unitree` 用户已启用 systemd linger，服务不随最后一个 SSH 会话退出。系统启动时网站从原生控制状态开始，不自动进入自训练策略。

```bash
systemctl --user status b2-console.service
journalctl --user -u b2-console.service -n 60 --no-pager
systemctl --user stop b2-console.service
```

## 2026-11-01 后腿动作输入修复

实机两次启动后 0.101 秒和 0.112 秒出现位置输入丢失；参考动作在第 1 秒才开始起立。诊断确认低层接管后 sport 两条流均停止，而 odom 仍以约 500 Hz、lf/odom 以约 20 Hz 更新。本版修复订阅和坐标系衔接，保持两个模型的权重、PD、动作映射与 locomotion 输入不变。

动作进度按实际执行的参考帧计算，暂停时不再由墙钟推进到 100%。`hindstand_trace.jsonl` 记录后腿策略每帧的实测关节、位置来源、目标和推理时间，供后续实机结果复查。控制交接后重新读取当前传感器，避免第一帧使用交接前的旧快照。

原生服务重启时的 SDK `3102` 表示发送失败；恢复原生控制后对尚未发送的请求重试，SDK 响应超时等执行结果未知的请求不重放。这属于通信交接处理，没有新增操作门槛或锁定。

`tests/shadow_inputs.py` 在机器人读取真实状态并做冻结参考帧推理，全程不创建电机发布器、不改变控制模式。数据链路检查通过不代表后腿实机动作已经完成复测。
